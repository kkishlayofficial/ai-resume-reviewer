# AI Resume Studio

An end-to-end AI-powered resume optimization platform. Upload a PDF or DOCX resume, let AI convert it into a structured editable format, compare it against a target job description, receive explainable ATS and technical evaluations, apply intelligent improvements with one click, re-evaluate the updated resume, and download both a professional analysis report and an optimized resume ready for job applications.. Upload a PDF or DOCX resume, paste a job description, and receive a structured analysis — including ATS alignment, technical depth, communication quality, strengths, weaknesses, missing keywords, actionable patch-based improvements, and a job fit verdict — all generated by a Groq-hosted LLM with structured JSON output.

Every improvement can be applied directly to the structured resume with one click. Applied items are visually highlighted in the Step 2 editor. After applying changes, re-evaluate to see the updated score — the app tracks the before/after delta so progress is always visible.

The updated resume can be downloaded as a formatted PDF or DOCX. A separate PDF analysis report can also be downloaded from the dashboard.

## How It Works

The application follows a 3-step wizard:

```
Step 1 — Upload
  └── User uploads a PDF or DOCX resume
  └── Backend extracts raw text (pdfplumber / python-docx)
  └── Heuristic validation confirms the file is a resume
  └── LLM parses the text into a structured Resume model
       (contact, summary, experience, education, skills, projects, certifications)

Step 2 — Edit & Optimize
  └── AI converts the extracted text into a structured Resume model
  └── User edits sections directly instead of raw text
  └── AI recommendations can be applied with one click
  └── Applied improvements are highlighted
  └── User pastes a job description and selects experience level
  └── AI review is generated

Step 3 — Dashboard
  └── Overall score + ATS / Technical / Communication sub-scores with reasoning
  └── Score deltas shown after re-evaluation (e.g. 78 → 91  +13)
  └── Skills, Strengths, Weaknesses, Missing Keywords
  └── AI Resume Improvements — patch cards with "+ Add to Resume" buttons
  └── Applied counter (Applied: 2 / 5) and Re-evaluate Resume button
  └── Job fit verdict with explanation
  └── Download analysis report (PDF) or updated resume (PDF / DOCX)
```

All state is persisted to `localStorage` — a page refresh never loses progress.

## Resilience & Error Handling

### Multi-Model Fallback (Backend)
The LLM service implements automatic model fallback for structured JSON output tasks. If a model is rate-limited, overloaded, or doesn't support strict JSON schema, the backend automatically retries with the next model in the priority list:
1. `openai/gpt-oss-120b` (primary)
2. `meta-llama/llama-4-maverick-17b-128e-instruct`
3. `meta-llama/llama-4-scout-17b-16e-instruct`
4. `llama-3.3-70b-versatile`

Auth errors (401/403) fail fast; network errors (connection failures) are not retried. The last encountered error is raised if all models fail.

### User-Friendly Error Messages (Frontend)
HTTP errors from the backend are mapped to clear, actionable user messages instead of exposing raw API details. For example:
- `503` → "The AI service is temporarily unavailable. Please try again shortly."
- `429` → "The AI service is currently busy. Please wait a moment and try again."
- `504` → "The AI service took too long to respond. Please try again."
- `413` → "Your resume file is too large. Please upload a file under 10 MB."

All error codes (400, 401, 403, 413, 422, 429, 500, 502, 503, 504) have mapped friendly messages defined in [frontend/src/services/resumeApi.ts](frontend/src/services/resumeApi.ts#L205-L230).

Each recommendation card in Step 3 carries structured metadata that drives automatic patching:

| Field | Description |
|---|---|
| `section` | Target resume section: `summary`, `experience`, `skills`, `projects`, `education`, `certifications` |
| `operation` | `append` — adds new content \| `replace` — rewrites specific existing text |
| `content` | The exact text to insert or replace with |
| `target` | (`replace` only) The existing text to be overwritten |
| `item_name` | (`experience` / `projects`) Company or project name to locate the right entry |
| `priority` | `high` / `medium` / `low` |
| `reasoning` | 1–2 sentences explaining why the change matters for the target role |

Clicking **+ Add to Resume** patches the structured `Resume` model directly, marks the affected bullet / chip with a `✦ AI` badge in Step 2, and increments the Applied counter. Clicking **Re-evaluate Resume** re-scores the patched resume and shows the improvement delta.

## Getting Started

### Prerequisites

- Python 3.11+
- Node.js 20+
- A [Groq API key](https://console.groq.com)

### Backend

```bash
cd backend

# Create and activate a virtual environment
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Copy the example env file and fill in your key
cp .env.example .env
# Edit .env — set GROQ_API_KEY

# Start the dev server
uvicorn main:app --reload
```

The API runs at `http://localhost:8000`.

### Frontend

```bash
cd frontend

# Install dependencies
npm install

# Copy the example env file (default points to localhost:8000)
cp .env.example .env

# Start the dev server
npm run dev
```

The app runs at `http://localhost:5173`.

> **Mock mode:** Set `MOCK_MODE = true` in `src/services/resumeApi.ts` to develop the full UI with hardcoded sample data and no running backend.

## Deployment

Both services are deployed separately on Vercel.

| Service | Live URL |
|---|---|
| Frontend | https://ai-resume-reviewer-rho-rust.vercel.app |
| Backend | https://ai-resume-reviewer-be.vercel.app |

### Deploy the backend

1. Import the repo into a new Vercel project — set **Root Directory** to `backend`
2. Add environment variables:
   ```
   GROQ_API_KEY     = your_groq_api_key
   ALLOWED_ORIGINS  = https://your-frontend.vercel.app
   ```
3. Deploy — Vercel auto-detects `vercel.json`

### Deploy the frontend

1. Import the repo into a separate Vercel project — set **Root Directory** to `frontend`
2. Framework preset: **Vite**
3. Add environment variable:
   ```
   VITE_API_BASE_URL = https://your-backend.vercel.app
   ```
4. Deploy

## Scoring Formula

| Dimension | Weight | What it measures |
|---|---|---|
| Technical | 50% | Technologies, tools, and experience explicitly stated in the resume |
| ATS | 30% | Keyword and qualification alignment with the job description |
| Communication | 20% | Clarity, structure, and quantified achievements |

All scores are integers 0–100. The LLM evaluates against the selected experience level (Junior / Mid-Level / Senior).

## Known Limitations

- PDF and DOCX only — no image resume support, no OCR
- Scanned PDFs (image-embedded) return empty text
- No authentication or rate limiting at the application level
- Groq free tier has strict TPM limits — large resumes + long JDs may hit rate limits
- No session history — only the current session is stored
- Vercel Python serverless functions have a cold start on first request (~1–3 s on free tier)
